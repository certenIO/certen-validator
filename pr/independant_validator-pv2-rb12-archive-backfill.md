## 1. Prefix records (`pkg/finality/prefix.go`)

A leg whose window lies below the first block the capture loop scanned asks for its window (clipped to the part below that block) with `finality.RequestPrefix`: one insert-only gap row `gap/<to>/capture_prefix` at `L1Block=from`, zero hash, bytes `CGAP1 || from || to || "capture_prefix"` (a function of (from, to): any number of validators write the same bytes; tested with 7 concurrent askers). From then on the existing gap machinery applies unchanged: fills, ends, `GapsIn`, hole-aware coverage. Policy (`PrefixPolicy{MaxBlocks, Floor}`, zero = off) is exact at its bounds (a window of MaxBlocks passes, MaxBlocks+1 is `over_budget`; `from == Floor` passes, `Floor-1` is `below_floor`); the budget counts the UNION of the windows. The bound is read from the rows the validator can see, with the read and the write of one request serialised within a process (the upgrader runs several builds at once; gated test with a store that pauses the first write); validators (separate processes) asking at the same instant can each pass the bound, so the union can exceed it by at most one window per other validator (6 x 3,601 blocks for seven); it never grows without a request.

## 2. Coverage (`baseposted/build.go` search)

`l1_capture_not_covering` is now decided from the recorded windows, not only from the first scanned block: the part of the leg's window below the scanned region must lie wholly inside recorded prefix windows (`PrefixCovers`, edges tested). When it does not, the leg is `l1_capture_not_covering` with `prefix_state` (off / below_floor / over_budget), `prefix_lowest_l1_block`, `prefix_blocks`; when it does, the search continues and an unfilled block of the window makes the leg `l1_capture_gap` (open / unavailable_proven / retention_expired), never "not posted yet". A window that starts inside the unfilled prefix is therefore never pending-forever; a channel whose frames are all captured is still accepted only after the verifier's own checks (unchanged). A window whose blocks are ALL filled and holds no channel is the plain pending `l1_posted_unproven` of every other covered window (finding F-ab-3). Only keys are read to decide coverage (test: zero row reads for a leg with no captured block). The window comes from the L2 provider's answer, which is untrusted: wherever that answer decides coverage below the scanned region (a durable request, or the verdict that the leg predates the capture) its transactions must hash to the transactions root of the leg's own header, else the leg is the named `l2_block_content_mismatch{block}` and nothing is written (hostile test: three lying answers, zero prefix rows, the real leg then covered within the same budget). A complete window (every block captured or filled, the capture cursor at least 96 blocks past its end) that holds no channel is the determinate `l1_posted_not_found{from,to,covered_to}` (class failure: exponential back-off of the F17 table), not the 2-minute pending of a window still being scanned; a window within 96 blocks of the cursor stays pending (exact edge tested).

## 3. Backfill (`baseposted/prefix.go`, `backfill.go`)

- Verification per block is the SAME `Capturer.CaptureBlock` as the live loop and the gap backfill (header hash, tx trie, KZG, systemConfigAt state proof via the archive provider, batcher == signer, header number == height asked, from train2): reused, not forked. A row that fails any check is never stored.
- Order: (1) blocks of windows with no proven-unavailable block, oldest first; (2) the holes of the live range (unchanged random pick); (3) blocks of windows that hold a proven-unavailable block, oldest first. Justification: providers prune oldest blobs first, so each block has a deadline and the oldest is due soonest (earliest deadline first saves the most blocks); a leg is covered only when ALL its blocks are, so a window that can no longer complete from these providers must not take budget from windows that can, but its remaining blocks are still captured last so that an archive finds them ready. The brief's "newest first" was weighed and rejected: with the measured rates (a whole window fits in well under an hour) it would let the oldest blocks expire first for no gain.
- Seven validators, one database: a chunk of 8 blocks is claimed with one insert-only row `gapclaim/<chunk>` whose KEY holds the 10-minute period and whose BYTES hold the claimant; the first writer wins, every other claimant meets the store's own `ErrCaptureConflict` and has lost (a named outcome, counted as `certen_finality_prefix_lease_total{outcome="lost"}`), the holder claiming again is a no-op, and nothing needs releasing (a claim ends with its period). A store that cannot take a claim ends the prefix phase of that step: no claim, no fetch. Test: seven validators with all captures failing (so no fill ever helps) fetch 56 blocks exactly once each.
- Pace/budget exactly as gapfill: the same `GapBackfillLoop` tick, `CERTEN_FINALITY_GAPFILL_BLOCKS_PER_TICK` blocks (default 8), one at a time, the same 16 MiB reserve. The holes keep a quarter of every tick (at least one block) while one is due, so a prefix of any size, failing or not, cannot starve them (probe: 1000 failing prefix blocks and a hole: the hole is attempted in the first step); what a class cannot use goes to the next.
- The spacing audit (`runtime/gapfill.go audit`) now starts at the loop's first cursor row. Without this, captured prefix blocks below the scanned region (with the unrequested stretches between windows) would have been read as outages and recorded as `spacing_unproven` gaps over the whole history between them (fail-before: 511-89999 and 90001-1000109 recorded in the test; the whole 115k-block span in production).
- `Backfiller.OnFill` tells a consumer (the Train 3 index) of every closed block.

## 4. unavailable_proven

- A pruned answer of the Teku class (HTTP 400 "Insufficient data columns", recorded in `baseposted/testdata/beacon_gone`) is counted as a gone answer like a 404/410; any other 400 is not.
- `unavailable_proven` still needs >= 2 distinct beacon hosts (`MinGoneHosts`, hosts counted by `hostKeyOf`) on 3 observations over >= 30 min; past retention a gone answer is `retention_expired`. The slot of the block is recorded FIRST (`gapslot/<block>`, a function of the block; another slot is the named conflict); an end is never visible without it, and a failure that names no slot is never turned into an end.
- The leg's `l1_capture_gap` carries, when its worst piece is terminal: `needs=blob_archive`, `newest_gone_l1_block`, `newest_gone_slot`, `gone_hosts`, and `oldest_served_slot` (the slot of the first captured block above the gone ones; left out when its header row does not parse).
- No endless retry: blocks proven unavailable or past retention are asked again once a day (`CERTEN_FINALITY_PREFIX_REPROBE_SECONDS`), the newest block of each of at most 16 runs; when one is served, every block proven unavailable is asked again.
- Metrics: `certen_finality_prefix_windows{chain,state}` (set on every tick, from the first, tested non-zero when it should be), `..._requested_blocks`, `..._backfilled_blocks_total`, `..._lease_total{outcome}`. Alerts in `pr/rb11-alerts.md` (unavailable_proven/retention_expired > 0 for 1 h = owner: OD4; open > 0 for 24 h with no progress; lease errors).

## 6. Arbitrum (item 5): the SequencerInbox batches posted before the capture started

Measured: 12 level-2 legs were `awaiting_batch_post` for batches posted 4-19 days before the arbposted capture (batch rows begin at N=884,511, L1 11,958,041); the builder had no coverage decision at all. Delivered, with the same discipline as Base:

- **Window.** The L2 header carries the L1 block number the sequencer saw (mixHash bytes 8..16: sendCount, l1BlockNumber, arbOSVersion) and the SequencerInbox accepts a batch only within its time bounds of that number, so a message with L1 block number m is in a batch posted at an L1 block in [m - futureBlocks, m + delayBlocks]. The pinned deployment's `maxTimeVariation()` was read with eth_call on 2026-10-23: delayBlocks 7200, futureBlocks 64 (constants `MaxDelayBlocks`, `MaxFutureBlocks` in arbposted/coverage.go; the window is 7,265 blocks). The header is the leg's own: it is used only when its hash equals the block reference's hash, so the request is derived from nothing a provider said (hostile test: a forged reference writes no row). The earlier estimate of 7,501 blocks used mainnet-like time bounds and is superseded.
- **Request and coverage (`arbposted/coverage.go`).** A leg with a standard-transaction block whose batch is not among the captured ones asks `finality.RequestPrefix` for the part of its window below the first cursor row minus 64; not requested (extension off, below the floor, over budget) is the named `l1_capture_not_covering` with `prefix_state` (`archive_provider` is `n/a`: Arbitrum proofs are taken near the head and need no archive); requested and not yet scanned or with an unfilled block is `l1_capture_gap`; scanned completely, with the cursor 96 blocks past the window end, and no batch holding the block is the determinate `l1_posted_not_found` (the same registered codes and F17 classes as Base); a window still ahead of the cursor stays `awaiting_batch_post`.
- **Scan (`arbposted/capture/prefix.go`).** Blocks of a requested window have no row to fill under (an event every ~7 blocks), so `finality.RecordGapScan` writes one insert-only row `gapscan/<to>` at `from` ("the SequencerBatchDelivered logs of [from, to] were read completely and every event in them is captured"; `GapsIn` treats the range as filled). One range of at most `CERTEN_FINALITY_PREFIX_ARB_SCAN_BLOCKS` (default 400, 1..2000) per tick, oldest first, claimed per chunk with the same lease as Base (`finality.Lease`, moved out of baseposted; `baseposted.Lease` is an alias), through the capture's own `captureBatch` (log address and topic, header hash == the log's block hash, the transaction in that block, accumulator consistency, batch record and calldata as one unit): the batch rows are byte-identical to the live scan's (test). A range with an event that does not capture, or a provider log outside the asked range, is not marked and is read again. The blobs and the near-head proofs of the batches a scan found are retried by the live machinery at a bounded rate (6 blobs and 62 proofs per tick) and not on the old cadence. The batch is bound to the Bridge's accumulator by the verifier (unchanged); the capture adds no poster check beyond what the live scan does (finding F-ab-8).
- Metrics/log/shape: the same `certen_finality_prefix_*` series for chain 421614 (windows complete/open, requested blocks, scanned blocks, claims), C9/C12 and the report script read `gapscan` rows.
- What still waits for INDEX-B: `LoadBatches` reads every batch row (3,185 now, about 5,000 more once the 12 legs' windows are scanned); the lookup by sequence number is INDEX-B's.
